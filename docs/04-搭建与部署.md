# 04 · 搭建与部署

两条路：**本机跑**（10 分钟，适合先验证）和**云服务器跑**（30 分钟，7×24 不用管开机）。

> 工作流跑在谁的电脑上，就依赖谁的电脑在 11:00 开着。想稳定每天收到，必须上云。

---

## 一、本机跑（10 分钟）

### 1. 准备 n8n

需要 n8n 1.x 以上。没有的话一行命令起一个：

```bash
docker run -d --name n8n -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n
```

浏览器打开 `http://localhost:5678`。

### 2. 拿推送 token（PushPlus）

1. 打开 <https://www.pushplus.plus>，微信扫码登录
2. 「发送消息」→「一对一推送」→ 复制「你的 token」
3. **微信关注「pushplus 推送加」公众号**（不关注收不到）
4. **必须实名认证**（个人中心 → 实名认证）

> 第 4 步是硬要求：未实名账号调用接口会返回成功但实际发不出。这个坑很多人踩过。
> 免费额度 200 条/天，本项目每天 2 条，够用。

想推给多个人：建一个「群组」，把群组编码填进 `PUSHPLUS_TOPIC`，群成员扫码加入后都能收到。

### 3. 拿模型 Key（DeepSeek）

<https://platform.deepseek.com> → API Keys → 创建 → 复制。

模型名用 `deepseek-flash`（旧名 `deepseek-chat` 已下线，填错会 404）。充 10 元够跑几个月：每天 1 次、输入约 5000 token。

> 不填也能跑——带背卡片会降级为台账轮换，背诵内容不变，只是看不到"今天为什么押这个"。

### 4. 导入工作流

n8n 画布右上角 `⋯` → **Import from File** → 选 `workflow/kaoyan-daily.json`。

导入后应该看到 5 个节点**已经连好线**：

```
每天11点 → 今日日课 → 推送日课 → 热点带背 → 推送带背
```

### 5. 填 Key（两个节点都要填）

打开节点 `推送日课` 和 `推送带背`，顶部四行：

```js
const PUSHPLUS_TOKEN = 'PLEASE_REPLACE_WITH_YOUR_TOKEN';
const PUSHPLUS_TOPIC = '';          // 留空=只发自己
const DEEPSEEK_KEY  = 'PLEASE_REPLACE_WITH_YOUR_DEEPSEEK_KEY';
const DEEPSEEK_MODEL = 'deepseek-flash';
```

**两个节点都要填一样的值**——它们各自独立发一条消息，是两份代码。

### 6. 验证 → 发布

点 **Execute workflow**，约 1 分钟（抓 B 站 + 7 个政策站 + 10 篇正文），微信收到两条后点 **Publish**。

正常输出长这样：

```
=== 节点1 今日日课 ===
日期 2026-10-30 | 第 1 天 | 距初试 50
分配 {"841":35,"数学":45,"政治":20,"英语":20} 总 120 分钟 | B站: 3 条

=== 节点3 热点带背 ===
保留条数 11 → 母题数 6 | 库母题数 9 | 政策速览 11 条
    新质生产力          政策3条  分40
    生态环境监测与评估     政策3条  分37
  ★ 长江大保护与水域生态    政策2条  分25

=== 节点4 推送带背 ===
LLM: 正常
展开母题: ["yangtze"]
模型选择: {"id":"yangtze","生态":[1,3],"政治":[1]}
```

如果 `LLM` 一行显示 `AI 未启用` 或 `AI 调用失败`，说明 Key 没填或余额不足——**内容照常推送**，走兜底轮换。

## 二、云服务器跑（30 分钟）

本机跑的问题很实际：11:00 没开机，那天的卡片就永久丢了（窗口虽然后续能补看，但推送不会补发）。

### 1. 买服务器

| 项 | 选什么 |
|---|---|
| 规格 | 2 核 4 GB（够跑 n8n + Postgres，本项目每天 1 次执行） |
| 镜像 | Ubuntu 22.04 LTS 64 位 |
| 系统盘 | 40 GB SSD |
| 地域 | 国内任意 |

腾讯云「轻量应用服务器」/ 阿里云「轻量服务器」都行，比 ECS/CVM 便宜且够用。

### 2. 初始化

```bash
ssh root@<你的公网IP>
timedatectl set-timezone Asia/Shanghai     # 时区必须改，否则 cron 会错 8 小时
curl -fsSL https://get.docker.com | bash
systemctl enable docker
```

### 3. 起服务

把 `deploy/` 下的两个文件传到服务器，**先改三个值**：

```yaml
POSTGRES_PASSWORD: CHANGE_ME_DB_PASSWORD     # 数据库密码，随机串
N8N_ENCRYPTION_KEY: CHANGE_ME_RANDOM_STRING  # 加密密钥，一旦定下不能再改
```

> `N8N_ENCRYPTION_KEY` 用来加密存进数据库的凭证。**改了它，之前存的凭证全部失效**——第一次就设好，之后别再动。

```bash
docker compose up -d
docker compose logs -f n8n        # 看到 "Editor is now accessible" 即可
```

浏览器打开 `http://<公网IP>:5678`。

### 4. 两件安全相关的事

- **改 n8n 的默认端口或加反向代理**，别把 5678 裸奔在公网上
- **云服务器安全组只开必要端口**（22 / 80 / 443）

### 5. 把工作流搬上去

服务器上一套全新的 n8n 是空的：重新导入 `workflow/kaoyan-daily.json`，重填两个 Key，重新 Publish。

> 本机那套的凭证不会跟着 JSON 走——JSON 里只有占位符，这是脱敏的必然结果。

## 三、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 微信收不到，n8n 显示成功 | PushPlus 未实名 / 未关注公众号 | 个人中心实名 + 关注「pushplus 推送加」 |
| 消息内容被截断 | 超过 PushPlus 2 万字上限 | 代码里有截断保险，调小 `PICK_N` 或减少 `MAX_E`/`MAX_P` |
| 带背卡片显示"AI 未启用" | Key 没填 / 余额不足 | 充值是前提，余额用完后会静默降级 |
| 推送时间不对 | 服务器时区是 UTC | `timedatectl set-timezone Asia/Shanghai` |
| 同一批内容反复推 | 台账没生效 | 检查 `beibeiHistory` 是否被清空 |
| 抓不到政策 | 站点改版 / 反爬 | 7 个源里坏 1~2 个不影响整体，改 `SOURCES` 里的选择器 |

## 四、日常运维成本

| 维护动作 | 频率 | 改动位置 |
|---|---|---|
| 改推送时间 | 偶尔 | 触发器 cron 表达式 |
| 加一个日期提醒 | 偶尔 | `今日日课` 的 `REMINDERS` 数组加一条 |
| 换一批手动情报 | 每周 5 分钟 | `今日日课` 的 `INTEL` 数组 |
| 加/改背诵知识点 | 按需 | 改内容库后重新构建，见 [05-定制与维护](05-定制与维护.md) |
| 确认它还在跑 | 每天 | 微信收到两条即为正常 |
