# 05 · 定制与维护

## 这套工作流不是通用模板

它最初是给**一个具体考生**做的，因此有六个地方是按那个人的报考信息写死的。要给别人用，这六处必须全改，否则他收到的还是别人的信息。

| # | 定制项 | 改哪里 | 说明 |
|---|---|---|---|
| 1 | 日课起点 | `今日日课` 顶部 `START_DATE` | 决定「第几天」「距初试几天」 |
| 2 | 初试日期 | `今日日课` 顶部 `EXAM_DATE` | 同上 |
| 3 | **报考点省份** | `今日日课` 的 `本省` | 决定外省政策丢掉哪些（外省名单由「全部省份 − 本省」自动算出） |
| 4 | 官方通知源 | `今日日课` 的 `NOTI_SOURCES` | 研招网 ×2 + 招生单位官网 |
| 5 | 四科与专业课 | `今日日课` 的 `BANK_841` / `BANK_MATH` / `BANK_POL` | 不考数学二的要整块换掉 |
| 6 | 关键日期提醒 | `今日日课` 的 `REMINDERS` | 准考证、初试、考场、成绩、复试 |

**第 3 项最容易漏，而且漏了不会报错。** 外省过滤靠「全部省份 − 本省」算出来，`本省` 没填对，就会静默丢掉真正需要的通知——考点安排、入场须知这类通知都是省级教育考试院发的。不会报错，只会"莫名其妙收不到"，比报错难查得多。

同理，第 4 项里的招生单位官网如果没换，用户会一直收到**别人学校**的招生公告。所以仓库里的这份 JSON 里，这些位置全部是占位符：

```
<TARGET_SCHOOL_HOST>   ← 招生单位招生页域名
<目标院校>              ← 招生单位名称（通知源、卡片文案）
<招生单位>              ← 同一名称在 AI 提示词里的称呼，单独一处，别漏
<考点城市> <考点代码> <考点名称>   ← 报考点
<本省>                 ← 所在省份
<YOUR_REG_NO>          ← 报名号（示例文案里的登录提示）
```

导入后搜一遍 `<`，逐处替换即可。

## 内容库怎么改

背诵内容不在工作流里，在两个独立的库文件：

| 文件 | 作用 | 结构 |
|---|---|---|
| `content/政策考点映射库.js` | 政策 → 考点的映射规则 | 20 个母题：关键词 / 生态锚点 / 政治锚点 / 权重 |
| `content/考点详解库.js` | 可直接背诵的原文 | 9 个母题：生态要点 + 政治要点，每条 100~180 字 |

改库之后不能直接生效——工作流 JSON 里的代码是**从这两个库生成的**。

原因很实际：n8n 的 Code 节点只有一坨 `jsCode` 字符串，四个节点的代码加起来超过 10 万字符，20 个母题和 141 条要点都在里面，手改必错。所以做了一个构建链路：

```
政策考点映射库.js + 考点详解库.js
        │  （注入 → 生成 4 个节点的代码）
        ▼
节点 1 日课与提醒 / 节点 2 推送日课 / 节点 3 热点带背 / 节点 4 推送带背
        │  （组装 → 导出）
        ▼
考研每日一站工作流.json  →  导入 n8n
```

**仓库提供的是这条链路的成品**（可直接导入的 JSON + 两个内容库），构建脚本本身没随仓库发布——它是中间产物密集的一次性工具，价值不如成品。想改内容的实际做法是：改库 → 重新生成 → 重新导入，这一步目前在本机完成。

## 三个必须知道的局限

### ① 政策抓不全的部分，靠带背补

有些母题某天只能抓到弱素材（比如"莆田海上森林""水资源公报"这种边角新闻）。但带背卡片照常给出必背条目——**因为知识点不依赖当天有没有好政策**。

政策只是引子，理论才是分。这也是为什么内容库是资产、抓取只是入口。

### ② 政治时政的具体表述必须自己核

库里只收长期确立的规范表述（"共抓大保护、不搞大开发"这一类），**不含当年会议的具体提法、数字、文件编号**。

这部分每年都在变，必须查肖四肖八和官方文件。刻意不写的理由很简单：写错比不写更害人。

### ③ 20 个母题里只有 9 个有完整详解

其余 11 个能召回、能押方向，但展开不出可背原文。这是有意的取舍——详解要逐条对齐教材、逐句核对表述，写一条的成本远高于列一个母题。宁可 9 个完全可靠，不要 20 个半真半假。

直接后果要说清楚：**每天参与轮换的池子是这 9 个，池子轮完约 9 天**，不是 20 天。补齐一个母题的详解，池子就多一天、复用周期就长一天——内容资产的厚度直接决定轮换空间。

## 可调参数速查

| 想改什么 | 参数 | 默认 | 说明 |
|---|---|---|---|
| 推送时间 | 触发器 cron | `0 11 * * *` | 每天 11:00 |
| 每天背几个母题 | `PICK_N` | 1 | 改大 → 内容变长，注意 2 万字上限 |
| 每个母题背几条 | `MAX_E` / `MAX_P` | 4 / 3 | 生态 / 政治 |
| 每天练多久 | `DAILY_MINUTES` | 120 | 决定四科时间分配 |
| 台账保留天数 | `beibeiHistory` 窗口 | 14 天 | 防重复用，喂给模型的是最近 3 天 |
| 抓取时间窗 | `NOTI_WINDOW_DAYS` | 21 天 | 手动执行放宽到 60 天 |

## 从零改造的成本估算

给别人用这套东西，实际要动的是：

| 步骤 | 耗时 |
|---|---|
| 换六处定制项（含重写四科题库） | 1~2 小时 |
| 扩充内容库（按新专业课重建映射） | 数天，看科目 |
| 部署到云服务器 | 30 分钟 |
| 调抓取选择器（站点改版时） | 每次 10 分钟 |

**真正的成本不在工程，在内容。** 这也是这类产品的本质：代码是壳，内容体系才是壁垒。
